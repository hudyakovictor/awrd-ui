# 1. ТРИ СЛОЯ БЕЗ ДУБЛИРОВАНИЯ — АРХИТЕКТУРНЫЙ ПРИНЦИП

Ключевая проблема, которую ты назвал: «как сделать, чтобы не совпадали главы академии, карты навыков и дерево навыков». Решение — каждый слой отвечает на **свой** вопрос и живёт в **своём** экране:

```
  │             — ось ДЕЙСТВИЯ           у каждой карты)     decision-картах   имён     │

  └────────────────────────────────────────────────────────────────────────────────────┘

  Враг не учит и не награждается за гринд. Враг ПРОВЕРЯЕТ и ВОЗВРАЩАЕТСЯ.
```

**Правило нулевого дубля (жёсткое, для всей команды):**
1. Ни одно название не встречается в двух системах. «Higher Timeframe» — это карта; узел дерева называется «Многомасштабное чтение»; урок называется «B12. Таймфреймы: одна история в двух масштабах».
2. Глава ≠ ветка дерева. Глав 10 (A–J), веток дерева 3 (Рынок / Сделка / Дисциплина). Одна глава кормит 2–3 ветки одновременно — поэтому спутать их невозможно структурно, а не только визуально.
3. Карта ≠ узел дерева. Карта прокачивается использованием (I/II/III), узел дерева прокачивается **телеметрией качества**: 30% уроки + 40% безошибочные применения карт + 30% победы над Entities домена. Узел нельзя «выучить» — его можно только «наиграть чисто».

**Как это выглядит для игрока:** он проходит урок в Академии → в награду получает/усиливает Карту → применяет её в decision-картах и боях → чистые применения наполняют узел Дерева в профиле → на пороге узла просыпается Entity → победа над Entity фиксирует узел и открывает следующие связи дерева. Три экрана, один поток данных, ноль повторов.

# 2. CORE LOOP — ЗАМКНУТЫЙ ЦИКЛ ИЗ 8 ТАКТОВ

```
        ┌──────────────────────────────────────────────────────────────────┐
        │                                                                  │
        ▼                                                                  │
  [1] УЧУ (урок Т+П, ≤400 знаков + разобранный пример)                     │
        │  дофамин: новая карточка знания                                  │
  [2] ПРИМЕНЯЮ (Р: decision-карты, ставка = решение, не деньги)            │
        │  retrieval practice №1                                           │
  [3] ПОЛУЧАЮ РАЗБОР (Д: debrief в R-единицах + «объясни почему»)          │
        │  formative feedback + self-explanation                           │
  [4] ЗАКРЕПЛЯЮ (recall-пачки +1/+3/+7/+16/+35 дней, микс из ВСЕХ          │
        │  пройденных глав — interleaving живёт здесь, а не в новых темах) │
  [5] ДОКАЗЫВАЮ (mastery-gate: N чистых применений в разных контекстах)    │
        │  незаметный для игрока счётчик                                   │
  [6] СРАЖАЮСЬ (Entity ранга I «выявляется» — сюжетное событие,            │
        │  на деле — замаскированный экзамен на перенос)                   │
  [7] РАСТУ (узел Skill Tree фиксируется в профиле, ветка тянется дальше,  │
        │  открывается следующий сегмент главы / глава на 65%)             │
  [8] ВРАГ ВОЗВРАЩАЕТСЯ (ранг II через ~7 дней, ранг III через ~21–60:     │
           новый контекст, конфликт сигналов, меньше подсказок) ───────────┘
```

Такты 1–3 — минуты. Такт 4 — дни. Такты 6–8 — недели. Три вложенных цикла удержания: сессионный (сегодня хочу закрыть карточки), недельный (жду реванша с врагом), месячный (хочу зафиксировать ветку дерева и сертификат главы). Это и есть замыкание: **Академия производит карты → карты производят телеметрию → телеметрия будит врагов → враги фиксируют дерево → дерево открывает Академию дальше.** Убери любой элемент — цикл разомкнётся.

**Экономика сессии (15–20 минут):** ~12 карточек = 60% новые/текущие decision-карты + 25% recall из старых глав + 15% события (враг/реванш/секрет). Соотношение взято из симуляции — при доле recall <20% ретенция проседает, при >35% падает ощущение прогресса.

# 3. АКАДЕМИЯ A–J: ПОЛИТИКА РАЗБЛОКИРОВКИ

## Вердикт по твоему вопросу «строго по очереди или 65%»

Симуляция (раздел 8) показала: разница между «строго по очереди» и «65%-overlap» по качеству усвоения **мала** (ретенция 0.82 vs 0.80), значит выбор делается по продуктовым соображениям — и тут overlap выигрывает чисто:

- **Убирает «стену»**: если игрок застрял на экзамене главы (например, H79 с порогом 85%), он не заблокирован полностью — может начать следующую главу и вернуться. Блокировка = главный триггер оттока в узких местах.
- **Даёт легальный interleaving**: две активные главы = чередование доменов, что даёт +0.04–0.07 к переносу навыка в симуляции.
- **НО: жёсткий кап = 2 главы.** Режим свободного выбора (3+ глав) в симуляции обрушил всё: перегрузка ×10 (13 confusion-событий против 1.2), ретенция −0.17, отток до 46%. Твоё опасение «это только запутает» верно ровно наполовину: путает не параллельность, а **отсутствие ясной основной линии**.

## Итоговые правила
1. Глава N+1 открывается при **65% прогресса** главы N (13 из 20 сегментов, включая все [Р]-карты сегментов).
2. Одновременно активны максимум 2 главы; UI всегда маркирует их как **«Основная»** и **«Следующая»** (следующая визуально приглушена, доступно только чтение [Т]+[П] и первые [Р]).
3. **Экзамен главы N обязателен для экзамена главы N+1** — сдать J-экзамен раньше H нельзя. Порядок сертификатов строгий, порядок изучения — полусвободный.
4. Recall-пачки игнорируют главы полностью: тянут decision-карты из всего пройденного. Interleaving через повторение, не через хаос новых тем.
5. Исключение: Stage H (Риск) — «глава-шлюз». Пока H79 не сдан на 85%, глава J недоступна даже на 65% от I. Риск-менеджмент — единственное, где мы намеренно ставим стену.

# 5. 40 ENTITIES: СИСТЕМА РАНГОВ И ПРАВИЛА ПОЯВЛЕНИЯ

## 5.1 Вердикт: ранги, а не новые враги

Использовать только 40 одноразовых сущностей — значит выбросить главный обучающий механизм. Симуляция дала самый большой эффект именно здесь: **возвращающийся усиленный враг = интервальное повторение + вариативный контекст в одном флаконе** (retention 0.80 vs 0.62; transfer 0.51 vs 0.24). При этом НЕ нужно рисовать 120 врагов — нужен один персонаж в трёх состояниях.

## 5.2 Правило появления (mastery-gate) — «враг выявляется, когда навык усвоен многократно и безошибочно»

Entity ранга I просыпается только когда по родной карте выполнено ВСЁ:
- ≥5 безошибочных применений подряд (fail обнуляет серию);
- в ≥3 разных контекстах (другой актив / таймфрейм / режим рынка);
- в ≥2 разных сессиях (нельзя нагриндить за вечер);
- recall-карточка навыка закрыта минимум на интервале +3 дня.

Игрок счётчик не видит — видит событие: скрепка-старец щурится: «Чуешь? За твоей спиной три недели стоял Fake Breakout Phantom. Пора.» Психологически это переворот: экзамен превращается в заслуженную охоту.

## 5.3 Три ранга и 8 осей усиления (из канона ТЗ)

| Ось усиления | Ранг I «Проявление» | Ранг II «Мутация» (+7 дней) | Ранг III «Апекс» (+21–60 дней) |
|---|---|---|---|
| Контекст | Тот же класс актива, что в уроках | Новый актив/таймфрейм | Чужой домен (навык из «Рынка» проверяется внутри сделки) |
| Подсказки | Контр-карта подсвечена | Подсветки нет | Рука содержит карты-обманки |
| Сигналы | Чистые | 1 конфликтующий сигнал | 2–3 конфликта, часть данных отсутствует |
| Горизонт | 1 решение | Серия из 3 связанных решений | Многодневный сценарий (позиция живёт между сессиями) |
| Комбинации карт | 1 родная карта | Родная + 1 вторичная | Комбо из 3 карт разных веток |
| Режим рынка | Тот, где навык учили | Смежный режим | Противоположный режим (тренд-навык в боковике) |
| Объяснение | Не требуется | Выбор верного обоснования из 4 | Свободное объяснение (проверка скрепкой), без него победа не засчитана |
| Перенос | — | Использован приём из предыдущей главы | Использованы приёмы из ≥2 предыдущих глав |

## 5.4 Бюджет контента (реалистичный)
- **Ранг I — все 40 врагов** (ручная постановка боя, 40 сценариев).
- **Ранг II — все 40**, но 70% генерируется шаблонно: тот же сценарий с заменой контекста/актива + 1 конфликт-сигнал из библиотеки. Ручной работы ~30%.
- **Ранг III — только 12 «апекс-линий»**: 10 боссов экзаменов глав (по духу главы: Stage D — Fake Breakout Phantom III, Stage H — Drawdown Leviathan III, Stage I — Revenge Wraith III…) + 2 капстоун-рейда (J98: System Breaker III; J99: финальная «Синдикат-волна» из 5 апекс-врагов подряд).
- Остальные 28 врагов на ранге III появляются **процедурно в пост-гейме (Arena+)** как ротация еженедельных охот — бесконечный эндгейм без нового арта.

## 5.5 Провал боя ≠ наказание
Поражение от Entity запускает протокол из канона: показать какой навык блокирует → какая ошибка повторяется → targeted practice (3–5 карточек точно по дыре) → разделить «не знал» (ошибка на recall) от «знал, но сорвался» (recall чистый, решение импульсивное — маркер дисциплинарного сбоя, идёт в ветку Дисциплина). Реванш через 2–4 дня, не сразу — иначе гринд вместо усвоения. Никогда не показываем «попробуй ещё 100 раз»: после 3 поражений подряд бой замораживается и скрепка меняет тип тренировки (worked example вместо retrieval).

# 6. SKILL TREE В ПРОФИЛЕ: 3 ВЕТКИ × 8 УЗЛОВ

Дерево — витрина идентичности (как на твоём макете: Рынок 8/24 · Сделка 5/24 · Дисциплина 5/24). 24 узла, у каждого 3 деления (I/III), итого 72 деления — они и есть «личный уровень» отдельно от кампании.

**Ветка РЫНОК:** Чтение цены → Уровни → Объём → МТФ → Фигуры → Контекст пробоя → Качество источника → Подтверждённый вход*
**Ветка СДЕЛКА:** Торговый план → Вход → Риск/прибыль → Stop Loss → Take Profit → Управление позицией → Безопасный стоп* → Анти-FOMO протокол*
**Ветка ДИСЦИПЛИНА:** Самоконтроль → Терпение → Проверка → FOMO → Антискам → Калибровка уверенности → Проверенный нарратив* → (закрытый узел легенды)

Узлы со звёздочкой — **кросс-веточные замки́** (как в твоём макете «Рынок + Сделка»): требуют делений из двух веток. Они делают дерево графом, а не тремя столбиками, и наглядно продают главную идею: трейдинг = пересечение анализа, исполнения и самоконтроля.

**Формула наполнения деления узла:** 30% уроки Академии (какие [Э] сданы) + 40% чистые применения привязанных карт + 30% победы над Entities домена. Следствие: узел невозможно закрыть только уроками — нужно играть; и невозможно только боями — нужно понимать. Деление III любого узла требует минимум одной победы ранга II. Дерево читается рекрутером/другом за 10 секунд: «у него Рынок 20/24, но Дисциплина 9/24 — понятно, кто он».

# 7. НАУЧНАЯ ОСНОВА: 10 МЕТОДОВ

Формат каждой строки: суть → эффект → механика → карта → Entity → тип задания → обратная связь → метрика → риск неправильного применения.

**1. Retrieval practice (приоритет №1).** Суть: извлечение из памяти укрепляет след сильнее перечитывания. Эффект: +долговременная ретенция (сильная доказательная база: Roediger & Karpicke 2006). Механика: [Р] decision-карты и recall-пачки — ядро каждой сессии; теория [Т] всегда ≤400 знаков, чтобы сессия состояла из извлечения, а не чтения. Карта: любая, эталон — Market Structure. Entity: Fake Breakout Phantom (каждый бой = принудительный recall). Задание: «реши без подсказки, потом сверь». Фидбек: немедленный, с показом правильного рассуждения. Метрика: recall-accuracy по навыку на интервалах +7/+35. Риск: превратить recall в узнавание (4 варианта с очевидными дистракторами) — дистракторы обязаны быть правдоподобными ошибками реальных трейдеров.

**2. Spaced repetition (приоритет №2).** Суть: растущие интервалы повторения побеждают забывание. Эффект: ретенция на месяцах (Cepeda et al. 2006). Механика: recall-пачки +1/+3/+7/+16/+35 + возвращение Entities R2/R3 как «тяжёлые» повторения. Карта: Set Structural Stop. Entity: Stop Hunt Kraken R2 через 7 дней. Задание: микс старых decision-карт. Фидбек: кривая памяти навыка в профиле («этот навык остынет через 4 дня»). Метрика: стабильность (дней до прогнозируемого падения recall <80%). Риск: пачки ощущаются рутиной → маскируем под «патрули» с наградой линии врага.

**3. Interleaving.** Суть: чередование типов задач учит РАЗЛИЧАТЬ ситуации, а не решать по шаблону. Эффект: +перенос, −шаблонность (Rohrer 2012). Механика: recall-пачки мешают домены; политика 2 активных глав; бои R3 мешают ветки. Карта: пара Enter Now vs No Trade Is a Decision (главное различение игры). Entity: Regime Shifter (в каждом бою сначала определи режим, потом действуй). Задание: серия, где подряд идут внешне похожие, но разные по верному действию сетапы. Фидбек: разбор «чем ситуация A отличалась от B». Метрика: точность классификации режима/сетапа на смешанных сериях. Риск: interleaving новичку слишком рано = перегрузка (симуляция FREE) — включаем смешивание только для материала, сданного на [Э].

**4. Elaborative interrogation.** Суть: вопрос «почему это верно?» углубляет след. Эффект: +понимание причинности. Механика: после верного ответа в 30% случаев скрепка спрашивает «почему?» с выбором обоснования; на боях R3 — свободный ответ. Карта: Define Invalidation. Entity: Hubris Dragon (принимает только ответ с названной причиной инвалидации). Задание: «выбери верное обоснование из 4, где 3 — правдоподобные заблуждения». Фидбек: показ типичного заблуждения и его цены в R. Метрика: доля верных обоснований при верных ответах (можно угадать действие, нельзя угадать причину). Риск: замедляет темп — дозируем 30%/бои.

**5. Self-explanation.** Суть: проговаривание собственного решения выявляет дыры. Эффект: +метапознание, −иллюзия знания. Механика: debrief [Д] после каждой сделки capstone: «вошёл бы я сюда сейчас?»; журнал сделок с обязательным полем «почему». Карта: Confidence Check. Entity: Narrative Siren (бой = отличить «красивую историю» от собственного проверяемого рассуждения). Задание: записать план сделки до входа, сверить после. Фидбек: скрепка подсвечивает противоречие плана и действия. Метрика: % сделок, где план и действие совпали. Риск: формальные отписки — журнал проверяется случайной выборкой на защите J99.

**6. Dual coding.** Суть: слово + схема кодируются двумя каналами. Эффект: +скорость усвоения абстракций. Механика: каждый [Т] = ≤400 знаков + ровно 1 схема (канон); каждая карта имеет пиктограмму-мнемонику (твой неоновый сет 40 иконок); враги — визуальные метафоры искажений. Карта: Liquidity Map (карта = буквально карта). Entity: Liquidity Hydra (головы = пулы ликвидности, отрубание головы = снятие стопов — образ, который невозможно забыть). Задание: разметка на графике (визуальный ответ), не только текстовый выбор. Фидбек: наложение верной разметки поверх разметки игрока. Метрика: точность визуальной разметки vs текстовых ответов того же навыка. Риск: украшательство вместо кодирования — схема обязана нести структуру, запрет на декоративные схемы в контент-гайде.

**7. Concrete examples.** Суть: абстракция усваивается через конкретику. Эффект: +понимание у новичков. Механика: каждый [П] — исторический сценарий с датой (каскад 24.02.2026, $600M ликвидаций — уже в каноне F57). Карта: Unlock Calendar. Entity: Unlock Titan (бои построены на реальных vesting-графиках). Задание: «вот реальная неделя рынка — найди то, что учили». Фидбек: что было дальше на самом деле + оговорка «одна история ≠ статистика». Метрика: перенос с исторического примера на свежий немаркированный кейс. Риск: hindsight bias («так это же очевидно было») — всегда показываем кейс ДО развязки и просим решение до раскрытия.

**8. Worked examples with fading.** Суть: сначала полный разбор эксперта, потом убираем шаги. Эффект: −когнитивная нагрузка новичка (Sweller). Механика: [П] = полный worked example → в [Р] той же темы скрыт 1 шаг → к экзамену главы скрыты все шаги → у Entity R2 исчезают подсказки (fading вшит в ранги врагов!). Карта: Minimum R Multiple. Entity: Expectancy Sphinx (R1 показывает формулу, R2 — только данные, R3 — данные с шумом). Задание: «продолжи разбор с шага 3». Фидбек: сверка по шагам, а не только итога. Метрика: сколько шагов игрок проходит без подсказки. Риск: слишком быстрый fading фрустрирует — скорость затухания привязана к телеметрии игрока, не к календарю.

**9. Pretesting.** Суть: попытка ответить ДО обучения повышает усвоение последующего материала. Эффект: +внимание к нужному месту урока. Механика: каждая глава открывается «разведboem»: 3 decision-карты по ещё не изученному материалу, результат не штрафуется. Карта: Volatility Context. Entity: Volatility Chimera (появляется в разведке как «непобедимый силуэт» — мотивационный крючок: вернёшься за ним через главу). Задание: «реши как умеешь». Фидбек: без оценки, только «запомни это место — вернёмся». Метрика: дельта усвоения тем с разведкой vs без (A/B). Риск: новичок примет провал разведки за свою тупость — обязательный фрейминг «никто не должен это уметь сейчас».

**10. Formative feedback.** Суть: обратная связь по процессу, а не по результату. Эффект: правильная атрибуция ошибок, защита от выученной беспомощности. Механика: весь debrief в R-единицах; оценивается решение, не исход (сделка по плану с убытком = «верно»; прибыльная сделка без стопа = fail — канон A7); телеметрия I88/J95. Карта: Discipline Over Profit. Entity: Approval Leech (бой = устоять перед «красивым PnL» в пользу процесса). Задание: оценить чужую сделку по процессу при скрытом исходе. Фидбек: два вердикта раздельно: «качество решения» и «удача исхода». Метрика: process-score (% решений по плану) как ведущая метрика всего продукта. Риск: игрок может решить, что результат вообще не важен — capstone J96–J99 возвращает связь с реальностью через 100-сделочную статистику.

# 8. СИМУЛЯЦИИ: МЕТОДИКА И РЕЗУЛЬТАТЫ

**Модель:** агентная Monte-Carlo симуляция. 150 виртуальных учеников на конфигурацию × 6 конфигураций (3 политики глав × 2 политики врагов) = 900 прогонов, повторено на 3 сидах (2700 траекторий). Ученик = параметры {скорость освоения, метапознание, упорство} + 40 навыков с кривой забывания Эббингауза (recall = exp(−Δt/стабильность)); успешный recall наращивает стабильность тем сильнее, чем труднее было вспомнить (эффект интервального повторения); interleaving растит перенос, но грузит слабое метапознание; отток растёт от фрустрации и перегрузки. Код: `sim/core_loop_sim.py`, сырые данные: `sim/results.json`.

**Результаты (сид 42; направления эффектов идентичны на сидах 7 и 2026):**

| Политика глав | Враги | Отток | Медиана дней до 99 | Ретенция +30д | Перенос | Перегрузка/чел |
|---|---|---|---|---|---|---|
| Строго по очереди | одноразовые | 41% | 93 | 0.65 | 0.19 | 0.0 |
| Строго по очереди | **ранги I–III** | 35% | 91 | **0.82** | 0.48 | 0.0 |
| **65%-overlap (кап 2)** | одноразовые | 35% | 92 | 0.62 | 0.24 | 1.4 |
| **65%-overlap (кап 2)** | **ранги I–III** | **32%** | **85** | **0.80** | **0.51** | 1.2 |
| Свободный выбор (3+) | одноразовые | 43% | 66 | 0.47 | 0.32 | **13.0** |
| Свободный выбор (3+) | **ранги I–III** | 43% | 68 | 0.63 | 0.42 | 12.5 |

**Выводы, устойчивые на всех сидах:**
1. **Ранги врагов — рычаг №1.** +0.17–0.19 ретенции и ×2 перенос в любой политике глав. Ни одно другое решение не даёт сопоставимого эффекта.
2. **Свободный выбор глав запрещён.** Быстрее проходят (66 дней — потому что учатся поверхностно), но ретенция рушится, перегрузка ×10. «Быстро прошёл» ≠ «усвоил» — важнейший аргумент против скорости как метрики.
3. **SEQ vs 65%-overlap — почти паритет по качеству** (0.82 vs 0.80), overlap чуть быстрее и с лучшим переносом. Решение в пользу overlap принимается по продуктовым причинам (нет «стены», есть агентность), и симуляция подтверждает, что за это не платим усвоением.
4. Повторяемые ошибки (~36–39 на ученика за прохождение) не зависят от политики — их лечит только targeted practice после провала (раздел 5.5), что закладываем в MVP.

**Ограничения (говорим честно):** это дизайн-инструмент для сравнения архитектур, а не доказательство эффективности продукта. Параметры откалиброваны на литературе по кривым забывания, а не на наших данных. После софт-запуска модель пересобирается на реальной телеметрии, и решения перепроверяются (фактор 12.10 скоркарты).

# 9. КАК СТАТЬ ЛИДЕРОМ ПО ИЗМЕРИМОЙ ЭФФЕКТИВНОСТИ (а не по заявлениям)

Стратегия: сделать эффективность усвоения **публичной метрикой продукта**.

1. **Внутренний золотой стандарт — Transfer Test:** банк из 200 немаркированных рыночных сценариев, не встречающихся в обучении. Каждому игроку — случайные 20 до старта (pretest) и изоморфные 20 после каждой главы. Дельта = наш «килограмм». Публикуем распределение, а не черри-пик.
2. **RCT против курса-контроля:** та же учебная программа (наш же контент A–J), упакованная как классический видеокурс+квизы, против полной игровой версии. 2 когорты × ≥300 человек. Первичные исходы: ретенция Transfer Test через 30 дней, completion rate, process-score в 100-сделочном paper-проекте. Вторичные: D30/D90 retention, время до уровня 50. Пре-регистрация дизайна (OSF) — «лидер рынка» станет проверяемым утверждением.
3. **Метрика, которую не имеет ни один курс:** «доля решений по плану» на 100 реальных paper-сделках (J96–J98). Курсы меряют просмотры; мы меряем поведение под давлением. Это и есть позиционирование: *«Курсы проверяют, что ты запомнил. Мы проверяем, что ты делаешь.»*
4. **Анти-метрики (публично отказываемся):** обещания доходности, скриншоты PnL, «сигналы». Уровень 99 = дисциплина и калибровка, не прибыль (канон). Это одновременно этика и юридическая защита.
